## Problems found (adversarial)

No blocking defect. The three required items behave as specified, and the positive path is intact. Items below are recorded so they are not rediscovered later.

- **Nit — the “now at” phrasing repeats itself on the very map that displaced the flow.** Repro: run A step 3, then read the line for Town05: `map /Game/Carla/Maps/Town05_Opt: config panel disabled (left the entry flow at /Game/Carla/Maps/Town05_Opt, now at /Game/Carla/Maps/Town05_Opt, which was not a panel-requested preview)`. `at` is also ambiguous between “the place you left” and “the place you went”. Not false, and the neighbouring `panel gate: left the entry flow: world changed <from> -> <to>` line disambiguates; but `left the entry flow for <to> (was on <from>)` would say it once.
- **Residual race in N2, not reproducible deterministically.** `ExpectedPreviewMap` is set in `STestPlatformUI::LoadSelectedMap` *before* the HTTP POST, while `HandleSessionState` clears it on any `state == "error"` answer. If the 0.2 s `/sessions/current` poll lands between those two points and the *previous* session is still in `error`, a live requested preview would lose its expectation and the arriving world change would be treated as leaving the entry flow (panel dropped although the panel asked for it). Window ≈ one poll interval plus the backend's old-session teardown; it needs a pre-existing error session. I could not make this happen on demand (the runs above always show the expectation surviving until the drop/consume point), and `bLoadingMap` serialises preview requests, so out-of-order failures are not a route.
- **Pre-existing, unchanged by this commit: a short `-Map L_TestPlatformEntry` is not classified as an entry map.** The shipped whitelist holds the full path, so `Test-EntryMap 'L_TestPlatformEntry'` is `False` both before and after the fix (`17-launcher-classification-matrix.txt`), even though the script header advertises `-Map` by map name and `architecture.md` says whitelist entries may be short names. The module's `IsEntryMap` has the same three-rule comparison, so launcher and product agree; only the documented usage is wider than the code.
- **No `CHANGELOG.md` entry.** `AGENTS.md` asks for one under `## LATEST Changes` for user-visible changes, and the launcher's printed classification and the new log lines are user-visible. The previous TestPlatform rounds also skipped it, so this is an inconsistency rather than a new regression.
- **Environment flake, not attributable to the commit.** The first launch of run F died at startup with an engine assertion before any TestPlatform code ran: `Assertion failed: RefCount.load(...) == 0 [Core/Private/Async/InheritedContext.cpp:130]` in `UE::FCurlHttpResponse::Release` on the `HttpConnectionPool` thread (`evidence-17/17-runF1-launch-crash-engine-assert.log`). Re-launching the identical command line was clean and produced run F. No changed file is on that stack.
