## Problems found (adversarial, non-blocking)

- **P1 — `cross` preset still carries 8 non-driving (sidewalk) waypoints.**
  Repro: `python probe_route_resolve.py …\data\routes\Town10HD.json` → `preset cross … non-driving lanes: 8`.
  Roads 258/718/769/942 are junction connectors whose `laneSection` declares only `lane 2 shoulder` + `lane 1
  sidewalk` (`check_sidewalk_lanes.py`); `gen_route_presets.lane_at()` falls back to "any non-zero lane" when no
  driving lane exists, so `lane_id=1` is stored and `session_runner._waypoint_at()` returns it (it only probes a
  single lane for a literal id), i.e. the overlay dips onto the sidewalk for 4 junction connectors.

- **P2 — 64 of 130 waypoints still store the `lane_id=-1` sentinel, and resolving it can land on the opposite
  carriageway.**
  Repro: `python written_polyline.py` → `loop 18/18 points drawn / stored lane replaced with a probed lane: 8`,
  `arterial 14`, `cross 8`, `turns 14` (and 64 never change because they were never generated). For `loop[0]` the
  probed lane points east (14.2°) while the route's first leg points south-west (`check_direction.py`: `00->01
  stored_lane=-1 used=1 leg=98.1 m bearing=-157.4 lane_yaw=14.2 delta=-171.6 <-- leg runs against the stored lane
  direction`). Consequence: wrong-way spawn, 494.6 m driven to a destination 94 m away, overlay covers ~20 %.

- **P3 — the overlay/trajectory mismatch is documented in the worklog only; `Platform/docs/architecture.md` §14
  still says no real run has ever happened** ("Town10HD 上主车是否真的行驶 … 从未端到端跑过", "路线预设叠加与主车
  实际轨迹是否一致" listed as unverified) even though the same commit ships an end-to-end run as evidence.

- **P4 — the new stall rule needs `throttle >= 0.05`, so a car the agent holds on the brake is never a stall.**
  Repro: stage obstacles the agent brakes for (e.g. queue of parked vehicles) → throttle 0, brake 1, no
  `ego_stalled` for as long as it stands. My first attempt with 14 construction cones is worse than that: the car
  simply drives over them (`shots-stall/02-t016.png`), so "block the lane with props" only works with a solid
  barrier (27 `static.prop.streetbarrier` worked → L1 #10). Matches the stated design ("throttle=0 等灯/保持一律
  清零"), but it silently loses the "permanently blocked, braking" failure mode.

- **P5 — pre-existing, not from this commit:** 17 `LogCarla: Error: Actor not Spawned` + 2 `has no SM assigned to
  the ISM` on every Town10HD load (18 in the pre-commit 10:37 log); and the panel stays hidden after a run because
  the world has left the entry map (`panel-after-stop.png`).
