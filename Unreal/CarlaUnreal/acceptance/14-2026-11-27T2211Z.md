## Problems found (adversarial)

No blocking defect found. Non-blocking observations, each with a one-line reproduction:

- **N1 — P1 holds only for pauses shorter than the ceiling (by design).** A live client that pauses longer
  than `carla.SyncCueCeiling` (default 300 s) is ejected: reproduce with `probe_pause.py --pause 310` and
  defaults — the ceiling path is unconditional, and rows 5/7 measured it firing with a client still connected,
  so a merely-silent live client is indistinguishable at that point (inferred from the code plus those
  measurements, not run for 310 s here). This is the deliberate trade-off that makes P2 a guarantee,
  it is stated in the cvar help and in `CHANGELOG.md` ("Raise carla.SyncCueCeiling … if a live client
  legitimately pauses that long"), and it is configurable — recorded, not a failure.
- **N2 — CHANGELOG wording nit.** `CHANGELOG.md:82` says the editor returns to asynchronous mode "as soon as no
  client is left on the RPC port"; in fact the grace waits 60 s *after* the last client leaves (row 11 measured
  exactly 60 s). The next bullet states the 60 s grace, so the pair is not misleading; the single sentence is
  imprecise.
- **N3 — stale comments.** `Source/TestPlatform/Public/TestPlatformApi.h:109` and
  `Platform/backend/app/session_runner.py:167` still name only `carla.SyncCueTimeout` as the thing that can drop
  synchronous mode; neither mentions the ceiling. Comment-only, not user docs.
- **N4 — legacy alias compatibility edge.** Before this commit any value ≤ 0 of `carla.SyncCueTimeout` meant
  "disabled". Now `-1` (and any other negative) means "defer to grace + ceiling", i.e. enabled; only `0`
  disables. A user who had set a negative value to disable silently gets the watchdog back. Undocumented values
  only, and the documented disable value `0` still works (row 10).
- **N5 — warning-only compile noise, not from this commit.** Compiling `CarlaEngine.cpp` still emits
  `You have included windows.h before MinWindows.h` and `warning C4005: "NOMINMAX": 宏重定义` from the
  `IPHlpApi` include block added by `f35b7c19c`; unrelated to the ceiling change, recorded as in round 13.
- **N6 — the liveness probe is port-wide, not session-aware.** `QuerySyncClientPresence` (`CarlaEngine.cpp:164-202`)
  reports `Present` for *any* ESTABLISHED TCP row whose local port is the RPC port, so a non-CARLA process
  holding 2000 keeps the grace from firing; only the ceiling ends the wait. That is exactly the intended
  design (bounded by the ceiling) and is documented, but it means the grace alone can never be the guarantee.
- **N7 — non-Windows trade-off unverified.** Where `GetExtendedTcpTable` is unavailable the function returns
  `Unknown`, and the grace path then ejects a merely-slow connected client at 60 s (`CarlaEngine.cpp:1156-1172`).
  Disclosed in `CHANGELOG.md`/`architecture.md`; cannot be exercised on this Windows-only host.
