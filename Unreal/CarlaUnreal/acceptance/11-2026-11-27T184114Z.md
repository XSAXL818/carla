## Problems found (adversarial)

**D1 — BLOCKING. After the panel starts the backend by itself, the panel still says the backend is not running and never loads its catalog.**

Reproduction (verbatim):
1. Confirm no backend: `Get-Process python -EA SilentlyContinue` → none; `Get-NetTCPConnection -State Listen -LocalPort 8765` → none.
2. `G:\Epic\EpicApps\UE_5.8_Carla\Engine\Binaries\Win64\UnrealEditor.exe "C:\GameProject\CarlaUE5\carla\Unreal\CarlaUnreal\CarlaUnreal.uproject" -game -windowed -ResX=1280 -ResY=720 -TestPlatformBackend=http://127.0.0.1:8765`
3. Wait ~90–120 s until `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` shows `run.py` (the panel spawns the terminal window).
4. `Invoke-WebRequest http://127.0.0.1:8765/health` → **200**; `Invoke-WebRequest http://127.0.0.1:8765/maps` → **200**.
5. Screenshot the game window: chip reads `已连接`, centre card reads `配置后端未运行（http://127.0.0.1:8765）`, map chip `未选地图`, no map list. Wait 60 s → unchanged. The backend terminal contains **zero** `GET /maps` lines.

Observed → why it fails:
- `STestPlatformUI::Construct` calls `Api->LoadCatalog()` exactly once (`Private/STestPlatformUI.cpp:163`), i.e. before the backend exists; `IsBackendReady()` is `Api->IsReady()` (`:1540`) and `IsReady` is `MapsCache.Num() > 0` (`Private/TestPlatformApi.cpp:210`). The offline overlay's visibility lambda (`:214-217`) therefore stays `Visible` forever, and `RebuildAll()` returns early (`:1661`), so map/route/vehicle/weather lists are never built.
- Nothing reloads the catalog when the backend appears: the reload is only wired to the 重试 button (`:239`, `:1531-1538`). Confirmed empirically — no `/maps`, `/vehicles`, `/weather`, `/algorithms` request is made after the spawn in any of runs A/B/D/E.
- Consequence for exactly the flow the user asked for: the operator watches the backend log in the new window while the application insists the backend is not running, and cannot select a map/route/vehicle until they discover and press 重试. The card's own text — `启动后会自动接管` ("it takes over automatically once started") — is false.
- Also makes the state indicator useless for the close test: the identical card is shown *before* and *after* closing the window (evidence 02 vs 03), so nothing on screen tells the operator the backend stopped except the top chip's `已连接` → `未知`.
- Attribution: the one-shot catalog load is older than this commit, but this commit's own evidence screenshot (`Platform/ui/backend-window-connected-topbar.png`) already shows `已连接` together with `未选地图`, and the commit's `architecture.md` §9 states the panel shows `配置后端未运行` *when the probe stops answering* — which is not what the build does. Whichever way it is attributed, the observable outcome of this change is a self-contradicting panel, so I cannot sign it off.
- Severity note: recovery is one click on 重试 (`ReloadCatalog` → `LoadCatalog` → `IsReady` true → overlay hidden). I could not confirm that click end-to-end: `PostMessage`-delivered clicks and a single synthetic screen click were not delivered to the Slate panel, and I did not keep firing real screen clicks (they land on whatever window is topmost on this shared desktop).

**D2 — minor (latent, documented). A python path containing a space breaks the launch command.** `SpawnBackend` embeds `"%s" run.py` inside an already-quoted `cmd /k "…"` for `wt`, which re-tokenises the line; the code comment admits a space in the interpreter path needs a wrapper. Not exercised (the conda path has no spaces).

**D3 — minor. The fallback's "plain console" is not a plain console on this machine.** Win11's default-terminal setting routes the `cmd /c start …` window into Windows Terminal (`class=CASCADIA_HOSTING_WINDOW_CLASS`, proc `WindowsTerminal`). Still visible, so the requirement is met, but the docs' "普通可见控制台窗口" describes intent, not what appears here. Additionally the fallback runs python directly (no `cmd /k`), so a python crash closes the window and its traceback — the traceback-retention property that motivated `cmd /k` is lost in the fallback (verified with a dummy child: window present while child alive, gone after it exits).

**D4 — informational. No CHANGELOG entry.** `carla/CHANGELOG.md` has a `## LATEST Changes` section and `AGENTS.md` asks for an entry on user-visible changes; this commit adds none (no prior TestPlatform commit has either, so it is a standing pattern rather than a regression here).

**Non-defect worth recording.** Closing the backend window produced no "close this tab?" confirmation and did not touch a second Windows Terminal window hosted by the same process — the `-w -1` isolation claim holds on this machine.
