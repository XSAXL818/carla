The third line is false: the run left the entry flow at **Town05**, not at the entry level, and it is the line an
operator consults to confirm exactly the requirement "loading the entry level again does not re-arm it". Read
literally it says the panel is off because the world changed *to* the entry level without a panel request — i.e. it
makes the whitelisted entry level look like the disqualifying map. `Platform/docs/architecture.md` §9.1 tells the
operator these reasons are the real basis (`原因写的是真实依据（entry map / backend preview load … / this run started
on <包路径>, which is not an entry map 等）`), so the document and the log disagree with the facts.

Cause (read-only diagnosis): `Private/TestPlatformModule.cpp:852` sets `LastRuntimeMapId = MapId;` before the audit
block, and the `bEntryFlowLeft` reason at `:874-878` prints `*LastRuntimeMapId` — by then it is the *current* map. The
departure map is not retained anywhere (the correct one only appears in the separate `panel gate: left the entry
flow:` line, which is itself correct). Fix direction: remember the departure map (e.g. a `EntryFlowLeftAt` member set
in the `:839-847` branch) and print that, or print `<departure> -> <current>`.

Everything else in this round's scope passed; this is the single blocking item and it is a one-line fix.

### Observations (not by themselves verdict-changing)

- **O1 — launcher misclassifies a dotted map path.** `-Map /Game/TestPlatform/Maps/L_TestPlatformEntry.L_TestPlatformEntry`
  (the object-path form, which is exactly the form `Config/DefaultEngine.ini` uses for `EditorStartupMap`) is not
  recognised by `Test-EntryMap`: the trailing `.L_TestPlatformEntry` defeats both the equality and the `…/<entry>`
  checks (`run-editor-lowquality.ps1:91-106`), so `$panelExpected` becomes false. The script would then wait for
  `LogWorld: Bringing World …` and print `the config panel is off on this map (not an entry map)` while the module
  does show the panel. Code-level; **not executed** end-to-end (the documented usage form
  `/Game/Carla/Maps/Town05_Opt` / short names work, and that is what was tested). Repro, if wanted:
  `pwsh -File run-editor-lowquality.ps1 -Map /Game/TestPlatform/Maps/L_TestPlatformEntry.L_TestPlatformEntry`.
- **O2 — a failed preview request leaves a stale expectation.** `ExpectedPreviewMap` is set before the HTTP call and
  only cleared when the matching world change arrives (`TestPlatformModule.cpp:848-851`). If the preview fails, the
  next *manual* `load_world` of exactly that town later in the same run would be treated as the panel's requested
  preview and would keep the panel armed — the one hole in "every other world change turns the panel off". Not
  reproduced (a failed preview was not staged).
- **O3 — the PIE reset is code-supported only.** PIE is barred here. `TickRuntime` is a core-ticker callback
  (`StartupModule`, `FTSTicker::GetCoreTicker().AddTicker`), it returns early whenever `GEngine->GameViewport == nullptr`
  and, under `GIsEditor`, calls `ResetGateForNewSession()` (which clears `RunStartMapId`, `bGateDecided`,
  `bEntryMapArmed`, `bEntryFlowLeft`, `bPanelManuallyShown`, `ExpectedPreviewMap`, `bPanelAdded`,
  `CachedViewportClient`). In `-game` that path is unreachable (`GIsEditor == false`), which is why no `-game` run can
  prove it. Residual risk I could not test: if the editor ever nulls `GEngine->GameViewport` *during* a PIE session
  (e.g. around a level change), the gate would reset and re-decide on the new map, i.e. hide the panel exactly when
  the preview town arrives.
- **O4 — untracked doc appeared during this review.** `Unreal/CarlaUnreal/Docs/HANDOFF-2026-11-28.md` (5.8 kB,
  mtime 08:08:45) is untracked and not part of `6458a5525`; it is not mine and I left it untouched. The tracked tree
  is clean (`git diff` empty).
- **O5 — pre-existing, still there (out of this commit's scope):** `GAreScreenMessagesEnabled = false` is set in
  `TickRuntime` and never restored when the panel is removed (`Panel 0` / `RemovePanelFromViewport`), so a process
  that showed the panel once keeps engine screen messages muted afterwards (code-level).
- **O6 — informational:** in the launcher's panel path the `session state: none map:` text is printed because the
  session is created a moment after the `test platform UI added` marker; not a regression (same as the pre-existing
  message) and the green "UI is up" line is correct.
- **O7 — pre-existing content errors, not attributable to the entry level:** `LogCarla: Error: Actor Name:
  InstancedFoliageActor_*/PB_Hotel* has no SM assigned to the ISM` appear whenever Town05/Town10HD is loaded (runs A,
  B, C, G, H) — also in a run started on Town05, so they are map-content noise, not caused by the entry level.
